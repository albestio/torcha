# agentorch improvements

Feature: close the defects that the first real end-to-end runs exposed in `agentorch` 0.3.0, before the first commit.
Read this file until `## Log`, then work only on the task you were given.

## Specs

**S1 — `start` must not type a program into a shell.** When a role's tab still exists and its terminal no longer has an agent, `agentorch start` must launch Pi by replacing that tab, never by injecting a command string. Evidence of the defect: `src/agentorch/commands/start.py:130` built `" ".join(shlex.quote(part) for part in argv)` and passed it to `send_text`; `hc send` wraps injected text in `<hc from="…">…</hc>`, which a bash receives literally and dies with `syntax error near unexpected token 'newline'`.
Observable: for that role the run issues `herdr-app do tab.close --id <old tab> --confirmed true` and `herdr-app do tab.new --name <role> --space <space_id> --folder <project> --argv '["pi","--session-id",…,"@.agentorch/bootstrap/<key>.md"]'`; **no** text is injected into any terminal for that role; the registry holds the new `tab_id`, `terminal_id`, `pid` and `session_id`; exit code 0.

**S2 — `--recreate` must honour `--fresh`.** `_recreate` never received `fresh`, so `agentorch start --recreate --fresh` silently resumed the old session instead of starting a new one.
Observable: with `fresh=True` the `--session-id` in the created tab's `--argv` differs from the registry's previous id and the registry is updated to the new id; without `fresh`, both equal the previous id ("resume the conversation, do not start another").

**S3 — the `start` behaviours that already worked must keep working.** A role whose agent is already running is reported as `ya está en marcha` and skipped. A terminal that is not a shell is refused with `el terminal no es un shell` and is not closed. With `--recreate` omitted, a missing tab reports the hint containing `--recreate` and the run fails. `start <role>` touches only that role. With `pi.bootstrap: "none"`, the role is skipped instead of launched.

**S4 — `_recreate` must take the ids from `herdr-app ls`, not from `tab.new`'s echo.** `init` and `_swap` both re-read the workspace (`wait_for_apps` + `extract_tab_ids`) because the echo is not the settled truth. A test must make the fake return a stale id from `tab.new` and show the registry keeps the one `ls` reports.

**S5 — the `--recreate` log line must state what actually happened.** It updated `entry["session_id"]` and then tested that same value to choose between `reanudada` and `sesión nueva`, so it always said `reanudada`. A fresh recreate must be reported as a new session.

**S6 — the `git` block a swap accepts must match the repository now.** `validate_handoff` checks the shape of `git` but compares it with nothing; only the manual `handoff validate --check-head` looked at the repository. So the document that `handoff run --swap` accepted and handed to a successor could state a `git.head` that no longer existed, disarming the successor's own staleness rule ("compare its `git.head` with `git rev-parse HEAD`").
Observable: `handoff run <role>` fails with a problem naming both shas when the repository HEAD differs from the `git.head` the agent wrote, and succeeds when they match; `RELEVO` states that `git` is measured by agentorch and must not be edited; a handoff that validates today still validates when HEAD has not moved.

**S7 — the skeleton must list every named tab with a live agent, except the setup tab.** `skeleton_from_live` (`src/agentorch/live.py:160`) ends with `for tab in ordered[:max_tabs]` and `max_tabs: int = 5`, so a team of six loses its sixth member silently. Observed in `career-ops` on 2026-11-24: seven tabs, all `renamed` with a live agent — `Senior Orchestrator, Scout, Communicator, Auditor, Builder, Coach, Agentorch` — and `agents.json` came out with five, `Coach` missing. `Agentorch` is the setup tab a previous interview renamed via `_mark_setup_tab`; it must never be adopted as a role.
Observable: with that same live state the skeleton contains `Coach` and does not contain `Agentorch`; any tab left out is named on stderr instead of dropped in silence. `proposal_from_live`, which shares the cap, follows the same rule for `discover` and for `init`'s fallback path.

**S8 — the team size limit is 10 and it is configurable.** The limit is not a hidden constant: the default is **10** and a project can change it in its own configuration.
Observable: with no configuration present the limit is 10 (a live state with twelve named role tabs yields ten, and the two left out are named on stderr); with the limit set to a different positive integer in the configuration, that value is used; an invalid value (zero, negative, not an integer) is refused with a diagnostic rather than silently ignored.
Note for the implementer: at `init` time the configuration does not exist yet — `start_interview` builds the skeleton *before* `write_default_config` — so the value has to come from the existing configuration **when there is one** and from the default otherwise. Do not invent a second config file for it.

**S9 — every text agentorch writes to the human is in English.** All CLI output (`log`, `note`, `error` in `src/agentorch/output.py` callers across `commands/*.py`), the argparse help and usage strings, and `RELEVO` — the prompt agentorch sends to a running agent — are English. Observed today: `Tab existente recuperada`, `ya está en marcha`, `el terminal no es un shell; no se envía nada a ciegas`, `deja fuera`, `El space … del registro ya no existe`, `No abrir la entrevista; materializar directamente.`
Observable: no CLI output produced by the package contains Spanish prose; `agentorch --help` and every `agentorch <cmd> --help` are English; `RELEVO` is English. Handoff documents written by the agents and the arbitrary text of tab names are not affected. Internal code comments and docstrings are out of scope: this is about what the tool says, not how it is written.

**S10 — a named tab excluded for having no live agent is reported.** `skeleton_from_live` requires `renamed and has_agent` (S7), so a named tab whose Pi died simply disappears from the skeleton, exactly as silently as the old five-tab cap did. Observed in `career-ops` on 2026-11-25: the `Coach` tab was named and present but its terminal had no program (`app=None`), so nothing was offered to the interview and nothing was said about it.
Observable: when a named tab is skipped because no agent is running in it, the run says so on stderr and names the tab and a way forward (`agentorch start <role> --recreate` once it is a role, or starting Pi in that tab). A tab excluded for being the setup marker, or as a bare unnamed tab, is not reported.

**S11 — the interview must ask only the roles that are empty, and say the truth about the rest.** `_interview_prompt` (`src/agentorch/commands/init.py`) writes "Every `role` and `instructions` is empty. Fill them from what each agent tells you" and the setup skill instructs "**Ask every agent in the list.**" Both are written for a first-time seed. When `init` runs on an existing configuration with some roles pending — which is exactly what `unfilled_roles()` triggers it for — the prompt lies, the spawned Pi asks the five agents that were already written, and their agent-written prose is exposed to being rewritten.
Observable: with one pending role among filled ones, the generated interview prompt names only that role as the subject of the interview and states that the others are filled and must not be touched; the setup skill carries the same rule; and the prompt contains no claim that every role is empty when one is not. A first-time seed, where every role is empty, keeps the current wording and behaviour.

**S12 — after the setup interview, the terminal keeps the focus and the logs.** `init` ends by selecting the space and the orchestrator tab unconditionally (`src/agentorch/commands/init.py:434-437`), so the moment the interview's Pi exits — including when the human closes it to finish — the view jumps away from the pane where agentorch is printing its summary and results.
Observable: when this run started an interview in the current pane, the run issues no `tab.select` or `space.select` towards `tabs[0]`, and instead logs where the orchestrator lives and that the logs stay in this tab. When no interview runs (plain `init`, or a configuration with nothing pending), the focus still goes to `tabs[0]`, which is deliberate feedback for a manual action. Reordering the orchestrator to position 1 is unaffected.

**S13 — a role is pending while either of its two fields is empty.** `unfilled_roles()` (`src/agentorch/commands/init.py`) only looks at `role`, so a role that has a `role` but no `instructions` is considered done and nothing ever completes it. That is exactly the shape `initial_tabs` and `discover` produce, whose placeholder reads `Not declared in the repository; describe it.` and whose `instructions` stay empty; S11's wording then tells the agent not to touch a field nobody ever wrote.
Observable: with a configuration where one role has `role` but empty `instructions` and another is fully written, `init` treats the first as pending and the interview prompt names it, saying which of its two fields is still empty; the fully written role is untouched. A role with both fields written stays out of the interview, and the first-time seed keeps working as it does today.

**S14 — `agentorch ls` lists the declared team against reality.** A human must be able to answer "does the configuration match what is on screen?" without reading `herdr-app ls` and `agents.json` by hand. Today it cannot: `status` compares the **registry** with Herdr and never sees a role declared in `agents.json` but never adopted — which is exactly how `Coach` stayed invisible — and `discover` lists live tabs without knowing the declared team.
Observable: `agentorch ls` prints one line per role declared in `agents.json`, in declaration order, carrying at least the key, the name, the terminal, the state and the session; then names the live tabs that are not in the team. A summary line states the three counts — declared, adopted, alive — so the human can compare numbers at a glance. States are the ones `status` already uses (`alive`, `down`, `missing`, `moved`) plus `not adopted` for a declared role with no registry entry. `ls --json` gives the same data machine-readable. The command is read-only: it never creates, closes or focuses a tab, and it does not replace `status`, which stays the one that rules on divergence.

**S15 — closing a tab parks the role, so `start` must not recreate it.** An agent whose work is out of focus is put to sleep by closing its tab and woken later, deliberately. A `start` that recreates missing tabs by default wakes every parked role at once and destroys that workflow. This spec replaced an earlier version of itself that asked for the opposite; see L20.
Observable: with a registered role whose tab no longer exists, a plain `agentorch start` reports the role as a failure naming `--recreate`, creates nothing and leaves the registry untouched, exit 1. With `--recreate` the tab is created, the recorded `session_id` resumed and the registry updated with the new ids and pid, exit 0. A session whose tab survives is still resumed either way. A terminal that exists but runs something which is not a shell is never closed under any flag.

**S16 — changing `pi.bootstrap` must reach the files `pi` reads.** The mode is not consulted at launch: it is rendered into `.agentorch/bootstrap/<key>.md`, and only two places write those files — `init` (configured mode) and the swap (`recover` for that role). `start` does not. So editing `agents.json` from `greet` to `recover` and running `agentorch start` launches the agent with the **old** prompt on disk, and nothing says so. Observed while answering a question about the modes on 2026-11-25: `grep -c 'Recovery protocol' .agentorch/bootstrap/*.md` returned 0 for a configuration that claimed `recover` would be in effect.
Observable: when the file on disk does not hold exactly what the configured mode renders, the launch refuses that role, names the file and the mode it was written for, and tells the human to run `agentorch init` to reconcile it; nothing is overwritten and the registry is untouched. `doctor` reports the same disagreement as a finding. When the file matches, the launch proceeds as today, and a swap still renders `recover` for the role it is about to relaunch.

**S18 — `status` carries the per-role detail that decides a handoff.** `status` says `alive` and stops, which answers nothing about the question the tool exists for: is this role close to filling its context, and is its handoff still true? The data is available without disturbing any agent.
Observable: for each registered role, `status` reports the newest handoff for that role — its age and its `git.head` — how far the repository has moved since (`git rev-list --count <handoff head>..HEAD`, and whether the working tree is dirty), and the tokens consumed by that role's last turn, read from its Pi session transcript. A percentage of the context window is shown only when the window is resolvable; otherwise the tokens are shown alone and the gap is stated, never guessed. A role with no handoff, no session id or no readable transcript says so per role instead of omitting the column. `--json` carries the same fields. Reading these sources never writes anything and never sends anything to an agent.
Note for the implementer: the transcript records `usage.totalTokens` and `model` per message but **not** the context window, so the percentage needs a window from somewhere else; treat it as best-effort and degrade loudly. The session store lives outside the project under Pi's own directory — read it defensively, by globbing the session id, and never fail the command because it is missing.

**S19 — every launched agent carries the team skill.** An agent can play neither half of the handoff protocol through the CLI: `recover` refuses the terminal that runs the command, because sending a message to yourself is pointless, and `handoff run --swap` refuses it too, because the swap closes that tab. The procedure therefore has to be in the agent's own context, and a skill that must be discovered on demand is one an agent can skip. Observed: the only packaged skill is `skills/setup/SKILL.md`, loaded by `init` for the interview; `pi_argv()` launches agents with the bootstrap reference alone.
Observable: `pi_argv()` returns `<executable> --skill <absolute path to the packaged skills/agentorch/SKILL.md> [--session-id <id>] @.agentorch/bootstrap/<key>.md` for every agent it launches, resolved from the package so the target project needs nothing; `bootstrap: "none"` still returns no argv at all; the setup interview's argv is unchanged. The skill teaches catching up — newest handoff by modification time, its `git.head` against `git rev-parse HEAD`, the working tree as the truth, the role in Engram, an honest report of what is done, pending and contradicted, and saying so and continuing when either source is empty — and handing over — the document's required shape, `agentorch handoff validate <path>` run from inside, and the swap run by the human or the orchestrator from a tab that is not the agent's. The cost is accepted: tokens in every session, by design. The README states the same, including the cost.
**S21 — a swap may reuse a handoff that already exists.** After a relief, the document is already written and validated; asking the agent to write it again costs a turn and rewrites what was just agreed. `handoff run <role> --swap --use-existing` uses the newest handoff that already validates instead of asking for a new one.
Observable: with a valid handoff on disk, `--swap --use-existing` relaunches the session with that document, states its age in the message, and never sends `RELEVO`. The HEAD check is not waived: if the repository moved since the document was written, the run refuses and says to ask for a new one. Used without `--swap`, the flag is refused with a message saying why. A role with no valid handoff on disk falls back to asking, and says so.
**S22 — every option is documented where a test can notice drift.** The CLI has grown past what a README paragraph can hold. `docs/cli.md` carries, per command, its positionals, every flag, what each does and the exit codes; a test asserts that every option the parsers define appears in that file, so the documentation cannot fall behind the code in silence.

**S20 — `init` reports live tabs outside the team and suggests, without writing.** `ls` names them and `init` stays silent, so a team can drift from its workspace without the command that reconciles the team mentioning it.
Observable: at the end of a run, `init` names the live tabs with an agent that are not declared in `agents.json` and states the role it would add for each, in one line; it writes nothing to the configuration, and `--json` carries the same list. A workspace whose tabs all belong to the team says nothing extra.

**S17 — `recover` on demand, inside a running session.** A role that has been parked or idle for a long time needs to catch up on the world, not to be replaced. Today the recovery protocol only reaches an agent at launch, where nobody is watching, or forced by a swap, which destroys the session.
Observable: `agentorch recover <role>` sends a catch-up message to that role's live agent and returns without touching the tab, the session id, the registry or the handoff; the agent answers in its own tab with what is done, what is pending and what the repository contradicts, after comparing its handoff's `git.head` with the current HEAD. The target is confirmed to be that role's own tab, not merely a terminal running the configured executable: a registry entry whose tab id no longer matches must be refused, because sending the wrong role's handoff path to another agent is worse than not sending; a tab that was merely renamed is a warning, not a refusal, since the id is the identity and the name is the human's label. A role with no running agent is refused with a message pointing at `start`, the terminal running the command is refused like the swap's guard, and an agent that is mid-turn is reported as queued rather than as answered. When there is no handoff, or Engram has nothing for the role, the prompt says to report that and continue instead of asking for a comparison that cannot be made. The prompt is its own text, neither the launch bootstrap nor `RELEVO`, and it names the project and the role.
